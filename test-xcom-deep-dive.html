🔬 X.com Deep Dive: Reveal Analysis

Analysis of X.com Reveal Issues

This page analyzes why reveals fail on X.com and tests potential solutions.

Identified Issues

Issue #1: Detection vs Extraction Mismatch

Problem: Detection checks isLikelyHidenlyMessage(node.data) on the original text node, but then extractCompleteText() aggregates from parents. If the node itself doesn't have enough invisible chars to pass the detection threshold, it's never extracted even if the parent has the complete message.

Impact: Messages split across many small nodes may not trigger detection.

Issue #2: TreeWalker Doesn't Guarantee Complete Message Collection

Problem: TreeWalker visits text nodes in document order. On X.com, the first delimiter might be in one subtree and the second in a completely different subtree that's visited later. By the time we find both parts, we've already processed and potentially missed the connection.

Impact: Split messages across different DOM branches may never be properly assembled.

Issue #3: Parent Aggregation Assumptions

Problem: Current logic assumes walking up 5 levels and aggregating all text nodes will find the complete message. But X.com's structure might have:

  • Visible text interspersed with invisible chars at the same level
  • Multiple separate text nodes that aren't direct descendants
  • Dynamic insertion of nodes that break the message apart

Impact: Aggregation may include too much visible text or miss parts of the message.

Issue #4: No Delimiter Position Verification

Problem: hasCompleteEncodedMessage() just counts delimiters (>= 2), but doesn't verify they're in the correct positions. A tweet could legitimately have multiple FEFF characters for other purposes.

Impact: False positives or extraction of wrong text between delimiters.

Proposed Solutions

Solution #1: Aggressive Parent-Level Detection

Instead of detecting at text node level, detect at element level by aggregating first, then checking. This ensures we don't miss messages split across multiple small nodes.

Solution #2: Better Delimiter Validation

Verify that delimiters wrap a valid encoded sequence (only invisible chars between them, no visible text). This reduces false positives.

Solution #3: Smarter Text Aggregation

When aggregating, separate text nodes into "visible" and "invisible" buckets, then only process invisible sequences.

Solution #4: Cached Extraction

Store the complete extracted text at detection time (already done) and ensure it's never re-extracted (current code does this for userscript but needs verification for extension).
